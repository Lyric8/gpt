# v3 交互重构计划

2026-09-18。目标不是给旧页面换颜色，而是减少完成一顿露营餐的阅读量和往返操作。

## 研究到设计

NN/g Progressive Disclosure（https://www.nngroup.com/articles/progressive-disclosure/）：把高频探索操作留在同一屏，将低频备份、配方审查、完整来源收起；食材和结果互相依赖，不做必须反复前进后退的分步向导。

NN/g Recognition Rather Than Recall（https://www.nngroup.com/articles/recognition-and-recall/）：每道菜以真实照片、名字、操作时间和核心食材帮助识别，不要求用户先阅读整张操作卡。

W3C WCAG 2.2（https://www.w3.org/TR/WCAG22/）：明确表单标签、键盘可达、可见焦点、合理触控尺寸、状态不能仅用颜色表示。

## 主路径

看菜谱 / 用现有食材 / 这顿菜单。分类多选决定当前候选范围。库存勾选按食材类别与工具分组、搜索、收起，换范围保留已拥有库存。结果立即区分全部具备、缺少食材和缺少工具。调味品也必须显式勾选，不能默认为有。

组合建议只从当前可做结果产生；按荤素主食、清口、少工具与主动操作时间选择，提供理由，不自动加入。不把拥有食材当成数量足够；组合展示需要核对合计用量。

## 源码边界

保留已验证的数量/备料/迁移引擎。拆出库存匹配纯函数、推荐纯函数、菜谱视图、库存视图、存储层、设计变量和布局。JSON 是菜谱与图片元数据入口；新增菜谱不用改视图分支。源码是多文件，离线 Release 是确定性自动打包的单 HTML，兼容既有发布/回滚契约。

## 验收

原引擎回归 + 新库存边界/组合约束单测 + Chromium 手机/桌面交互 + 键盘/搜索/刷新恢复/备份/图片检查 + 双构建 SHA256。只有实测通过后合入 main 并发布 Release；普通代码 push 不部署。
