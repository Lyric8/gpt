# V4 发布前只读核验：三项实测答复（零动作）

本轮零副作用：未部署、未改 main、未创建 Release、未改 Caddy 或任何服务器安全限制。以下全部是只读实测。

## 1. 单 HTML 上限 = 8,388,608 字节（8 MiB）；7.7MB 可过，但项目那 10,000,000 预算不是约束

- 门禁在 `/usr/local/lib/campfire/deploy-release`：`MAX_BYTES=$((8*1024*1024))`（第 20 行）+ `[ "$size" -le "$MAX_BYTES" ]`（第 67 行），下限 100 KiB（第 21/66 行）。
- 只计**页面字节**：请求行先被 `read` 吃掉（第 36 行），`head -c $((MAX_BYTES+1))` 之后才 `stat` 计 size（第 63/65 行）→ 上限就是正 8,388,608 字节，不含请求行。
- 换算：7.7 MiB = 8,074,035 B → 占门禁 96.25%，余量 314,573 B → **通过**；若 7.7 是十进制 7,700,000 B → 余量 688,608 B → **通过**。
- **提醒：项目自定的 10,000,000 字节预算不是约束**——10,000,000 > 8,388,608，真涨到那里会被门禁拒（报 `太大（8388609 字节），拒绝`）。硬上限就是 8,388,608，建议把项目预算改成这个数，免得按 10MB 估算而误判。
- 超限行为：`head` 在 8,388,609 字节处截断 → 体积检查先失败 → **不落盘、不安装**，不会留半成品。
- 其它两侧事实：每版会在 `/var/lib/campfire-kitchen/releases/<label>/` 存一份不可变副本（磁盘剩余 54G，单版 7.7MB 无压力）；线上 `Content-Length` 是原始字节，压缩只发生在 Caddy 传输层；同一 label 换内容会被安装器拒（hash 不符）。
- 我没有你的产物，实际字节数等你交付后可复测（只读）。

## 3. Caddy 没有另设 CSP → 加 `blob:` 只改产物，服务器零改动

- `/etc/caddy/Caddyfile`（`furrypant.com, www.furrypant.com` 段 + `:80` 兜底段）只设三条响应头：`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`Cache-Control "no-cache"`。Caddy 2.11.4。
- 线上实测（`http://127.0.0.1/` 与 `https://furrypant.com/` 响应头）：**没有** `Content-Security-Policy`，也没有 Report-Only。顶部 `import /etc/caddy/acli-external.d/hermes-webui.caddy` 只管 WebUI `:11320`，与本站无关。
- 现役 CSP 是**产物里的 meta 标签**（线上 v3 抓到的原文）：`default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:; connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'`。
- 结论：把 `img-src` 写成 `data: blob:` 即可（**别丢掉 `data:`**，现役页面靠它显示内联图）。服务器侧不需要任何改动、不需要 reload。
- 若你以后想改成响应头下 CSP，那才是服务器改动：我会先备份、`caddy validate`、再 reload，并按纪律放到维护窗口做——但那不是本次 V4 的必需项。
