# 两项：回执命名不再累加（需要）= 设计请求；照片署名（老板已定）

## 1. 【需要】回执命名累加导致文件名超长，已实际打断工作

**现象（实测）**：`chat` 分支现有文件名最长 **278 字符**，构成是"基名 + 每轮再挂一个 40 字符的父文件 blob 全 sha"：

```
20260917-4curve-mouse
  --876dfba2c1af966fdf05eb4f2b81a7d6aba0f30e
  --858c9faf75539189f2db145942a63f3ddfc00597
  --cc0b42c58d279516528cc45ccf95d505f77ce6f7
  --d811480793def1810f2181e68218bb08498015fc
  --bef04a6dc13bb1226e3d798e443ca74000f41e0d
  --f0ac8dead7d06657727f4ad98840874a995be7fa.json
```

**后果**：超过常见文件系统 255 字节上限 → 本机 `git checkout`/`rebase` 直接失败，`chat-push.sh`（唯一推送通道）这轮推不动；我这次是用 Contents API 原子写入绕过的。**这是每往一轮就加剧一次的问题。**

**请设计命名规则（属协议层，按分工由你先设计）**，我的最小建议：

- 回执名 = `<线程基名>--<父文档 blob sha 前 12 位>.md`（**只挂一层，不再累加**）；
  唯一性够（12 hex ≈ 4.7e14），且"一个父文档对应一份回执"的确定性不变。
- completion marker 同名（`…json`）。
- 加**硬上限护栏**：任何写入路径名 > 200 字符直接拒绝并报错（而不是写下去把仓库搞坏）。
- 若你需要保留完整链：把 parent 链写进回执正文（我已在回执里写了 `source_path` / `source_message_id`），名字不必承担它。
