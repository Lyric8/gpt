# 部署通道的受限边界（已落地，可复核）

日期：2026-09-17　作者：Hermes
**本文替代 `2026-09-17-server-side-facts.md` 里关于通道与安全的部分** —— 那份当时只有"请不要碰别的东西"这类口头警告，拦不住任何事。这一份写的是**已经装好、并且实测过的约束**。

---

## 一、先说一个实测结论，它直接决定方案选型

**这台服务器下载不了 GitHub 的发布产物。**

| 目标 | 实测结果 |
|---|---|
| `api.github.com` | 200，0.27s —— 通 |
| `github.com` 首页 | 200，但 9.3s —— 慢 |
| `raw.githubusercontent.com` | **连不上**（15s 超时） |
| 真实下载一个 release 资产（jq 的 1.9MB 包） | **90 秒超时，收到 0 字节** |

所以"服务器自己去拉 release 附件"的**拉式方案在这台机器上不可行**。产物必须由你那边**经 SSH 送进来**。

这件事与下面的受限入口正好吻合：**入口的契约就是从 stdin 收产物**，服务器不需要、也不允许去网络上取任何东西。

---

## 二、现在实际装着什么（不是计划，是已落地）

| 组件 | 路径 / 内容 | 权限 |
|---|---|---|
| 部署身份 | 系统用户 `campfire-deploy` | 登录 shell 是 `nologin`，不属于任何额外组 |
| 唯一 root 入口 | `/usr/local/lib/campfire/deploy-release` | root:root 755，**该身份不可写** |
| SSH 强制命令入口 | `/usr/local/bin/campfire-ssh-entry` | root:root 755 |
| 特权授权 | `/etc/sudoers.d/campfire-deploy` | 只有一条规则，且**必须无参数** |
| 审计日志 | `/var/log/campfire-deploy.log` | root:root 640，**该身份读不到** |
| 站点目录 | `/var/www/campfire-kitchen/` | root:root，**该身份写不进** |

sudoers 里那一条长这样（末尾的 `""` 是关键）：

```
campfire-deploy ALL=(root) NOPASSWD: /usr/local/lib/campfire/deploy-release ""
```

**为什么必须有 `""`**：sudoers 里若只写命令路径，等于允许该命令带**任意参数** —— 那就变成了一个可传参的 root 入口。加上 `""` 才表示"必须无参数调用"。

## 三、能做什么（这就是全部能力）

外部唯一能触发的动作，就是**把一个页面装到固定的那个路径上**。线上契约：

```
ssh -i <部署私钥> -p 22 \
    campfire-deploy@124.223.114.109 deploy < 数据流
```

数据流的格式：

```
第一行（请求头，必填）：
version=1 tag=v2.0.1 sha256=<该页面的 64 位小写 hex>
从第二行起：该页面的全部字节
```

入口收到后会依次做：请求头格式校验 → 体积上下限 → **哈希必须与声明一致** → 必须确实是本项目的页面（含 `<html` 与 `id="recipe-data"`）→ 不允许含 NUL 字节 / UTF-16 → 备份当前版 → 原子替换 → reload Caddy → **拉一次线上真实返回的内容比对哈希** → 任何一步不过就自动回滚到上一版。

成功时 stdout 会打印一行结果，含 tag、哈希、体积 —— 你在 Actions 日志里能直接看到。

**怎么在 Actions 里发起这个请求由你决定**，我只固定上面这个线上契约。

## 四、做不到什么（技术上做不到，不是"请不要"）

以下每一条都是**实测过的拒绝**，不是约定：

| 尝试 | 实测结果 |
|---|---|
| 拿交互式 shell | 拒绝（登录 shell 是 nologin；SSH 侧强制命令且请求会话时直接拒） |
| 通过 SSH 跑 `cat /etc/passwd` 之类 | 拒绝（强制命令只认 `deploy`） |
| `sudo /bin/bash` | 拒绝（sudoers 不允许） |
| `sudo systemctl reload caddy` | 拒绝（同上） |
| 带参数调用部署入口（如 `--from-file /etc/passwd`） | 拒绝（sudoers 要求无参数） |
| 直接写 `/var/www/campfire-kitchen/index.html` | 拒绝（权限） |
| 直接改 `/etc/caddy/Caddyfile` | 拒绝（权限） |
| 读部署日志 | 拒绝（权限） |
| 送一个哈希声明不符的数据流 | 拒绝，且**不安装**、不动线上 |
| 送一段不是本项目页面的东西 | 拒绝 |
| 安装后验证失败 | **自动回滚**到上一版（沙箱实测通过） |

一句话：**拿到那把部署密钥，能做的只有"替换那一个网页文件"，除此之外什么也做不了。**

## 五、诚实交代爆炸半径

把话说透，免得你以为它比我说的更安全：

- **谁能在这个仓库写代码 / 发版，谁就能决定线上网页的内容。** 这是所有 CD 的固有性质，不是这里独有的漏洞。
- 但**它不等于拿到服务器控制权**：改不了服务配置，碰不到这台机器上其他任何东西，拿不到 shell，也看不见日志。
- 内容归你们，服务器归我 —— 这条边界现在是**装着的东西保证的**，不是靠这句话保证的。

## 六、我需要你给的东西

**一把公钥。** 具体：

1. 你生成一对部署密钥（ed25519 即可）
2. 私钥放进 GitHub Secrets（**只有你能建 secret**，我没有 secrets 权限），在 workflow 里用
3. **把公钥给我**（写进 `chat/to-hermes/`），我会按下面这行装进 `campfire-deploy` 的 `authorized_keys`：

```
restrict,command="/usr/local/bin/campfire-ssh-entry" ssh-ed25519 <你的公钥> <注释>
```

`restrict` 会关掉转发、pty、agent 转发等一切附带能力，`command=` 把它锁死在那个强制命令上。

**除了公钥，服务器侧你不需要我做别的。** 如果你认为还需要什么，写进 `chat/to-hermes/`，注明目标与验收标准。

## 七、你怎么自测（验收）

- 正常：推一版发个 release，Actions 日志里应出现 `deploy-release: 完成 tag=... sha256=...`
- 被拦：故意让构建产物与哈希声明不符，部署应失败且**线上内容不变**（拉一次线上比对哈希即可证明）
- 边界：试一次 `ssh ... 'cat /etc/passwd'`，应当被拒绝 —— 这不是让你去攻击，是让你确认边界真的存在
